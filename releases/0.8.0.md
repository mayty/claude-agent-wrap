## What's Changed

### Breaking: provider interface restructured

Custom providers that subclass `Provider` or `LiteLLMProvider` must update
for the interface changes below. The [Sidecar ABC] is unchanged — it was
relocated verbatim.

| Aspect | Old (`0.7.1`) | New (`0.8.0`) |
|--------|------------------------|---------------|
| `Provider.__init__` | (none) | `__init__(self, sidecar_service, display_service)` |
| `Provider.get_pricing()` | public, returns `dict` or `{}` | `_get_pricing()` (private), raises `NotImplementedError` |
| `Provider.get_tiered_pricing()` | public, returns `dict` or `None` | `_get_tiered_pricing()` (private), raises `NotImplementedError` |
| `Provider.compute_cost()` | (none) | new public method with default implementation |
| `LiteLLMProvider._sidecar_config()` | returns `LiteLLMSidecarConfig` | returns `dict[str, object]` |
| `LiteLLMProvider.sidecars()` | constructs `LiteLLMSidecar` directly | uses injected `self._sidecar_service.create_litellm_sidecar(...)` |
| Provider package path | `agent_wrap/providers/<name>/` | `agent_wrap/domain/providers/<name>/` |
| Sidecar package path | `agent_wrap/sidecars/` | `agent_wrap/domain/sidecars/` |

[Sidecar ABC]: https://github.com/mayty/claude-agent-wrap/blob/0.8.0/agent_wrap/domain/sidecars/base.py

### Added: `AGENT_DAY_START_UTC` to control the `agent stats` day boundary

`agent stats` buckets usage into calendar days. The new `AGENT_DAY_START_UTC`
env var sets how many hours past UTC midnight a "day" begins, for hosts and
workflows where the host-local midnight boundary (the existing default)
doesn't line up with how the team wants usage bucketed. See
[docs/configuration.md] for the accepted range and an example.

[docs/configuration.md]: https://github.com/mayty/claude-agent-wrap/blob/0.8.0/docs/configuration.md#agent_day_start_utc-stats-day-boundary-offset

### Added: `agent stats --pattern`/`-p` to filter projects by name

`agent stats -p <regex>` restricts the report to projects whose recorded
registry path matches the given regular expression, for narrowing a large
registry down to one project or a related group. The synthetic `<orphaned>`
row is included only when the pattern also matches it.

### Added: live daily usage tracking feeds the statusline

The `agent logs` background viewer now tracks each day's token usage and cost
as log files are written, and continuously writes the running totals to
`~/.claude/usage.json`. The bundled statusline (`ops/statusline.py`) reads
this file to show today's cumulative tokens and cost (`Today: ↑in ↓out |
cost`) instead of the current session's cost, falling back to a hint to run
`agent logs` when the file is missing or more than 30 minutes stale.

### Added: `agent secrets` command with encrypted storage

A new `agent secrets` command replaces hand-editing plaintext secrets files. Four subcommands cover the full lifecycle: `agent secrets set <sidecar>` interactively prompts for each required credential and persists it, `agent secrets check <sidecar>` verifies every required secret is present and exits non-zero when any are missing, `agent secrets clear <sidecar>` removes all stored credentials for a sidecar, and `agent secrets cleanup` deletes orphaned keys that no longer belong to any known sidecar or provider. Secrets are stored encrypted instead of in plaintext. An existing plaintext file is migrated into the encrypted store automatically on first access and then deleted, so upgrading requires no manual steps.

### Changed: `agent run` prompts for missing secrets instead of failing

When `agent run` starts a provider or the Telegram sidecar and a required secret is absent, it now prompts for it interactively on the spot rather than aborting — the first run against a new provider just works with no separate setup step. On a non-TTY the run still fails, with a message pointing to `agent secrets set <name>`. Optional sidecars such as Telegram are silently skipped when their secrets are absent instead of aborting the launch.

### Changed: memory files relocated to a dedicated per-project mount

Memory files that persist across sessions now live at `.claude/memory/` instead of `.claude/sessions/memory/`, giving them their own dedicated mount separate from the sessions directory. On first launch after upgrading, existing files are automatically moved to the new location — no manual migration steps are needed.

### Changed: tab completion is now Python-native

Shell completions are now dynamically generated from each verb's argument
parser instead of a hand-maintained bash script, so completions stay in sync
with flag definitions automatically.

### Changed: `agent run` no longer prompts to update when launched headlessly

`agent run` and `agent rebuild` already run a best-effort check for wrapper updates on every invocation, prompting `Update agent-wrap now? [y/N]` when one is available. `agent run` now skips that check entirely when it detects a headless invocation — `-p`/`--print`, or `--bare`/`--safe-mode` — the same flags under which the Telegram sidecar is already skipped, since there is no one to answer the prompt and it would otherwise block waiting on input. See [docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.8.0/docs/configuration.md#agent_skip_update_check-auto-update-opt-out).

### Changed: `.agent_stats_leaf` no longer supports a custom display name

A transient project group's row in `agent stats` and the `agent logs` viewer is now always named after its `.agent_stats_leaf` marker directory. Any text previously placed inside the marker file to give the group a custom display name is no longer read — the file's presence still triggers grouping, but its content has no effect. See [docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.8.0/docs/shell-commands.md).

### Improved: `agent stats` no longer marks negligible unknown-model usage as unrecoverable

Previously any model missing from a provider's pricing table made its entire
cost total show as unknown (`?`) in `agent stats`. Now, if the usage would
round down to $0.00 even under the most expensive tier the provider knows,
it's reported as a known `$0.00` instead — reserving the unknown-cost marker
for models whose usage is large enough that the true cost actually matters.

### Improved: `agent logs` picks up new projects without a full rescan

Previously, adding a project to the registry while the `agent logs` viewer
was running triggered a full rebuild of the entire cache. Now only the newly
added project's sessions are scanned in, so the viewer stays responsive when
projects are registered while it's already running.

### Improved: the `agent logs` viewer

A broad round of improvements to the `agent logs` web viewer:

- Renders Claude's thinking blocks as their own labeled section next to the
  response and tool calls, with a placeholder when only a signature is
  present and no visible reasoning text.
- Renders image content as inline thumbnails, clickable to a full-size
  overlay, instead of raw JSON.
- Tags auto-approval classifier requests with an "auto" badge and shows them
  compactly as the evaluated command plus an Allowed/Blocked/Unparseable
  verdict and reason.
- Labels subagent tabs and markers with the subagent type and task
  description when it can match one, instead of a generic id and prompt
  snippet, and adds a dropdown selector for sessions with two or more
  subagents.
- Loads and updates sessions faster: session data streams in and renders
  progressively, project/session lists and recently viewed sessions are
  served from a warm cache, and a slow first startup shows a spinner instead
  of appearing to hang.
- Pretty-prints multi-field tool call inputs as indented JSON with
  `description` promoted to the top, while simple single-field inputs stay
  compact.
- Collapses session model lists to at most three grouped entries when a
  session used more than three models, with the full list on hover.
- Fixes duplicate provider names appearing in a session's provider list.
- Fixes raw internal placeholder text momentarily showing instead of real
  content while it finishes loading; a loading spinner now shows in its
  place.

### Fixed: `agent logs stop` no longer silently swallows a permission error

If `agent logs stop` lacks permission to signal the running viewer process, it
now reports the failure instead of suppressing it and reporting success.

### Other: `CLAUDE_CODE_ENABLE_AUTO_MODE` forwarding removed

Claude Code v2.1.207 dropped the requirement for this opt-in — auto mode is
now available by default on Bedrock, Vertex, and Foundry, with control moved
to `disableAutoMode` in `~/.claude/settings.json`. Setting
`CLAUDE_CODE_ENABLE_AUTO_MODE` in the host shell has had no effect since then,
so the wrapper no longer forwards it into the agent container. See
[docs/container-environment.md](https://github.com/mayty/claude-agent-wrap/blob/0.8.0/docs/container-environment.md).
