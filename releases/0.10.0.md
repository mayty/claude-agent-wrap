## What's Changed
### Breaking: the wrapper runs on its own pinned CPython, and `agent update` needs an idle host

`agent` no longer uses the host's `python3`. It runs the CPython version that
[python-pin.env](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/python-pin.env)
pins. The new
[bin/agent-bootstrap](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/bin/agent-bootstrap)
script downloads that version and verifies its checksum. Run the bootstrap one time in
each checkout after you upgrade:

```bash
/path/to/claude-agent-wrap/bin/agent-bootstrap
```

Until you do this, every `agent` command exits non-zero. The supported hosts are now
glibc Linux and macOS, on x86_64 or aarch64. The wrapper refuses a musl host. See
[docs/getting-started.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/getting-started.md).

`agent update` now refuses to start while Docker reports any agent container or sidecar
as active. `agent run` and `agent rebuild` do the same check.

### Breaking: a project Dockerfile must inherit from the base image

The final `FROM` in `.claude-agent-wrap/Dockerfile` must now name `claude-agent`. `agent
run`, `agent rebuild` and
[ops/validate-dockerfile-agent](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/validate-dockerfile-agent)
refuse every other image. An earlier stage of a multi-stage build still accepts any image.
Put your own base in a builder stage. Then copy the result into a final `FROM
claude-agent` stage.

### Added: spell checking in the prompt input

The base image now includes `hunspell` and its dictionaries. Each `agent run` makes spell
checking active for all projects. English and Russian are both active by default. Set
`AGENT_SPELLCHECK=0` to make the function inactive, or `AGENT_SPELLCHECK_LANG` to replace
the dictionary list. A new list needs one `agent rebuild --full`. See
[docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/configuration.md).

### Added: per-project startup scripts

Each `agent run` now runs `.claude-agent-wrap/startup.sh` from the project directory, if
`# agent-enable-startup: true` makes it active. The directive is off by default. The usual
example is a Docker network that the agent then attaches to with
`# agent-run-args: --network …`.

Be careful: the script runs on your host, outside the container, with your permissions.
Examine all of `.claude-agent-wrap/` before you launch an agent in a project from someone
else. See
[docs/docker-sandboxing.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/docker-sandboxing.md).

### Added: `agent inspect` reports the project image, the stale images, and a `--lite` mode

The details table now gets a `project image` row below the base image, for a project with
a `.claude-agent-wrap/Dockerfile`. The row names the `claude-agent-<agent-name>` image,
and tells you if it exists. It also gives the Claude Code version inside.

A fourth table follows the details. It names each registered project whose own image the
next `agent run` rebuilds, and gives the reason.

`-l`/`--lite` makes the report faster. It skips the npm version check, the size of the
logs tree, and the sweep for a stale project image. It names what it skipped. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/shell-commands.md).

### Added: the logs viewer starts itself on `agent run`

`agent run` now starts the `agent logs` background viewer for you, early in the launch.
The statusline segment `Today: ↑… ↓… | $…` then has a reader. The launch never waits for
the viewer. The viewer continues after the agent exits. `agent logs --stop` stops it, and
`AGENT_AUTOSTART_LOGS=0` makes the behavior inactive. See `docs/configuration.md`.

### Added: `agent run` checks the launch directory, and `agent inspect` reports the check

`agent run` mounts the current directory at `/workspace`. A home directory or a system
root is a bad target. `agent run` now names such a directory in red, then asks `Launch
here anyway? [y/N]`. The default answer is No, and Enter stops the launch.

A headless launch cannot answer the question, so `agent run` refuses it.
`AGENT_SKIP_SAFETY_CHECK=1` turns the check off. The details table of `agent inspect` gets
a `directory guard` row. See `docs/configuration.md`.

### Changed: the project Dockerfile moves to `.claude-agent-wrap/Dockerfile`

Per-project wrapper files now live in a `.claude-agent-wrap/` directory in the project
root. The image is a plainly named `Dockerfile` in that directory, beside the optional
`startup.sh`. `agent create` makes the new layout.

The old path still works: `agent run`, `agent rebuild` and `agent inspect` read it and
print a deprecation warning. To migrate, use
`mkdir -p .claude-agent-wrap && git mv Dockerfile.agent .claude-agent-wrap/Dockerfile`.
A project that has both files is an error. `.claude-agent-wrap/` goes into version
control, so make a loose `.claude*` pattern in `.gitignore` more exact. See
[ops/dockerfile-agent-guide.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/dockerfile-agent-guide.md).

### Changed: the wrapper creates the missing host paths that a mount needs

A `# agent-run-args:` line can mount host paths into the container. The wrapper now makes
those host paths before the launch, and you own them. If the container side is below
`/workspace`, the wrapper also makes the mount point in the project
(`-v /workspace/node_modules`). A read-only source is the exception: a `:ro` mount with a
missing host path stops the launch. Make that path, or remove `:ro`.

### Changed: attribution rules for the agents in your projects

[ops/default-CLAUDE.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/default-CLAUDE.md)
goes to consumer projects. The attribution rule now selects the line by the state of the
file. A file with no line gets `created` or `edited`. A file that already has a line does
not change.

Generated output is a new exception: a generator carries the line, and the files that it
writes carry none. `agent update` brings the new rules, unless you customized your copy.

### Changed: `agent run` builds a missing or stale image

`agent run` now builds the images that it needs. It builds the base `claude-agent` image
when that image is absent. It rebuilds the base image when the wrapper's docker build
iteration moves. It rebuilds a project image when the base image below it changes. Every
automatic build prints its reason. `agent rebuild` is now the explicit force.

The first `agent run` after this release rebuilds both images one time. An edit to your
own project Dockerfile still needs `agent rebuild`.

### Changed: `agent cleanup` also removes outdated docker images

`agent cleanup` now reclaims docker images, together with the logs and the registry
entries. The command removes the untagged leftovers of each rebuild. It also removes the
`claude-agent-<name>` image of a project that you deleted or renamed. It removes each
project image that `agent inspect` reports as stale. It also removes the LiteLLM and
Telegram sidecar images that the wrapper no longer pins.

A table shows each image with its size before the prompt. `agent cleanup --dry-run` shows
the same table, and then stops. See `docs/shell-commands.md`.

### Improved: errors and warnings carry a severity tag

Errors now print in bold red on a terminal, beside the yellow warnings and green
messages. Each error starts with `[ERROR]`, and each warning with `[WARNING]`, so the
severity survives a redirect or a pipe. The old `Error:`, `error:`, `usage:` and `note:`
prefixes are gone.

Four commands also use the correct stream. `agent inspect` prints its warnings on stderr.
`agent secrets check` ends with one error that counts the missing secrets. `agent stats`
no longer reports an empty result as a failure. Bare `agent` prints its command list on
stdout.

### Improved: the `agent stats` projects table fits the console

`agent stats` now measures the console. The projects tree gives back one path segment at
a time, until the table fits. The table becomes taller, and the totals do not change.
`COLUMNS` states the width when there is no terminal.

### Improved: the `agent logs` viewer renders each tool result, and the statusline reports the current day's usage

The viewer showed each tool result as one block of JSON text. An image that the agent
reads now appears as a picture. A click on the picture opens it at full size. A text
result now shows the text with the correct line breaks. The viewer shows the loading
indicator until a large result arrives.

The `Today: ↑… ↓… | $…` segment showed the previous day's tokens and cost on a day with no
usage. The count was correct again after the first request of the new day. `agent
logs` now writes the current day's total on every update, so an empty day reads as zero.
