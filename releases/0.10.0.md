## What's Changed
### Breaking: the wrapper runs on its own pinned CPython, and `agent update` needs an idle host

`agent` no longer uses the host's `python3`. It runs the CPython version that this project
pins in
[python-pin.env](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/python-pin.env).
The new
[bin/agent-bootstrap](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/bin/agent-bootstrap)
script downloads that version and verifies its checksum. There is no fallback to a system
interpreter. Run the bootstrap one time in each checkout after you upgrade:

```bash
/path/to/claude-agent-wrap/bin/agent-bootstrap
```

Until you do this, every `agent` command exits non-zero and prints that command. The
interpreter goes into a git-ignored `.python/` directory in the checkout, and uses
approximately 120 MB. The supported hosts are now explicit: glibc Linux and macOS, on
x86_64 or aarch64. The wrapper refuses a musl host, so an Alpine host that ran 0.9.0 no
longer works.

Python is no longer a host requirement. A host needs Docker, `tar`, `curl` or `wget`, and
`sha256sum`, `shasum` or `openssl`. `agent inspect` has a new `interpreter` row, which
gives both versions and how to correct a difference. See
[docs/getting-started.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/getting-started.md).

An update replaces the code that every live agent runs, and provisions its interpreter
again. Therefore `agent update` now refuses to start while Docker reports any agent
container or sidecar as active. It lists what it found, exits `1`, and merges nothing.
There is no override flag. `agent run` and `agent rebuild` do the same check, before the
`y/N` prompt, and also exit `1`.

Stop those containers to continue. `AGENT_SKIP_UPDATE_CHECK` makes those two commands skip
the check, but `agent update` always does it. An update that goes ahead also stops the
`agent logs` background viewer before the merge. The next `agent run` starts it again. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/shell-commands.md).

### Added: spell checking in the prompt input

Claude Code can mark misspelled words in the prompt input, but it includes no spell
checker. The base image now includes `hunspell` and its dictionaries, and each `agent run`
makes spell checking active for all projects.

English and Russian are both active by default. Hunspell accepts a word from any active
dictionary, so a prompt that mixes the two languages shows no errors. For the same reason,
a misspelled word that is correct in the other language also shows no error. Set
`AGENT_SPELLCHECK=0` to make the function inactive, or `AGENT_SPELLCHECK_LANG` to replace
the dictionary list, for example `AGENT_SPELLCHECK_LANG=en_GB,de_DE`. A new list needs one
`agent rebuild --full`. See
[docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/configuration.md).

### Added: per-project startup scripts

A project can need something on the host before its container starts. The usual example is
a Docker network that the agent then attaches to with `# agent-run-args: --network …`.
Each `agent run` now runs `.claude-agent-wrap/startup.sh` from the project directory, if
`# agent-enable-startup: true` makes it active. The directive is off by default. Its value
can also be a number of seconds, which replaces the ten-second budget.

The script needs no execute permission, because the interpreter comes from its shebang
line, or from `/bin/sh`. A failure stops the launch and releases the sidecars that the
launch started. A script that runs longer than its budget gets `SIGTERM`, and `SIGKILL`
five seconds later.

The script gets `AGENT_NAME`, `AGENT_INSTANCE_ID`, `AGENT_SIDECAR_NETWORK` and
`AGENT_BINARY`, in addition to the host environment. `AGENT_BINARY` is the absolute path
to the `agent` command, for read-only verbs only. `agent run` from inside the script makes
a deadlock.

Be careful: the script runs on your host, outside the container, with your permissions.
Examine all of `.claude-agent-wrap/` before you launch an agent in a project from someone
else. See
[docs/docker-sandboxing.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/docker-sandboxing.md).

### Added: `agent inspect` reports the project image, and a `--lite` mode

`agent inspect` showed the Claude Code version in the base image. That is not the version
that you run in a project that customizes its image. The details table now gets a
`project image` row below the base image, for a project with a
`.claude-agent-wrap/Dockerfile`. The row names the `claude-agent-<agent-name>` image, and
tells you if it exists. It gives the Claude Code version inside, and tells you if that
version is behind the registry. The same facts are in `--json`.

`-l`/`--lite` makes the report faster. It does not ask the npm registry for the newest
Claude Code. It also does not measure the size of the logs tree. It reports all other
content, and names what it skipped. Use it in a project `startup.sh`, where the full
report is too slow. See `docs/shell-commands.md`.

### Added: the logs viewer starts itself on `agent run`

The statusline segment `Today: ↑… ↓… | $…` reads a file that only the `agent logs`
background viewer writes. On a host where nobody started that viewer, the segment asked
you to run `agent logs`. `agent run` now starts the viewer for you, early in the launch.
The launch never waits for the viewer, and a viewer that cannot start is only a warning.
The viewer continues after the agent exits. `agent logs --stop` stops it.

The automatic viewer always uses the default port 8765, and `-p`/`--port` is for a viewer
that you start by hand. A headless `agent run` and the `litellm-anthropic-sub` provider
skip the automatic start. The statusline then has no reader. `AGENT_AUTOSTART_LOGS=0`
makes the behavior inactive. `agent inspect` has a new `logs viewer autostart` row, which
gives its state. See `docs/configuration.md`.

### Changed: the project Dockerfile moves to `.claude-agent-wrap/Dockerfile`

Editors, linters and highlighters select the Dockerfile grammar by filename, and
`Dockerfile.agent` matched nothing. Per-project wrapper files now live in a
`.claude-agent-wrap/` directory in the project root. The image is a plainly named
`Dockerfile` in that directory, beside the optional `startup.sh`. The build context is
still the project root, so a `COPY pyproject.toml …` line continues to work.
`agent create` makes the new layout.

The old path still works: `agent run`, `agent rebuild` and `agent inspect` read it and
print a deprecation warning. To migrate, use
`mkdir -p .claude-agent-wrap && git mv Dockerfile.agent .claude-agent-wrap/Dockerfile`. A
project that has both files is an error, and so is `# agent-enable-startup:` in the old
file.

`.claude-agent-wrap/` goes into version control, unlike the git-ignored `.claude/`
directory. Make a loose `.claude*` pattern in `.gitignore` more exact. See
[ops/dockerfile-agent-guide.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/dockerfile-agent-guide.md).

[ops/validate-dockerfile-agent](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/validate-dockerfile-agent)
follows the new layout. With no argument it validates `.claude-agent-wrap/Dockerfile`, and
warns if it uses a deprecated `Dockerfile.agent` instead. It also reads
`# agent-enable-startup:`, and reports a directive with no script, and a script with no
shebang line.

### Changed: the wrapper creates the missing host paths that a mount needs

A `# agent-run-args:` line can mount host paths into the container. Docker created a
missing path as `root`, and then you could not write to it or delete it. The wrapper now
makes those host paths before the launch, and you own them. If the container side is below
`/workspace`, the wrapper also makes the mount point in the project. Thus the shadow
volume pattern (`-v /workspace/node_modules`) leaves no root-owned directory. A read-only
source is the exception: a `:ro` mount with a missing host path stops the launch.

Make that path, or remove `:ro`. The wrapper reads `-v`/`--volume`, `--mount type=bind`
and `--tmpfs`, and identifies a host path as Docker does. Your image is still responsible
for the container side: make and `chown` a custom mount path there.

### Changed: attribution rules for the agents in your projects

[ops/default-CLAUDE.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/default-CLAUDE.md)
goes to consumer projects. It tells each agent to mark the files that it writes with an AI
attribution line. The old rule selected the line by the action, so an agent could add a
second line to a file. The rule now selects the line by the state of the file. A file with
no line gets `created` if the agent makes it, or `edited` if the file was already there. A
file that already has a line does not change, and two lines are prohibited.

Generated output is a new exception. A generator script or template carries the line, and
the files that it writes carry none. A file that you make with `sed`, a heredoc or a
one-off script is your work, and needs a line. Formats that permit no comments, such as
JSON, get no attribution. `agent update` brings the new rules, unless you customized your
copy of the file.

### Improved: errors and warnings carry a severity tag

An error printed in the terminal's default color, and you could not find it. Errors now
print in bold red on a terminal, beside the yellow warnings and green messages. Each error
starts with `[ERROR]`, and each warning with `[WARNING]`, so the severity survives a
redirect or a pipe. The old `Error:`, `error:`, `usage:` and `note:` prefixes are gone.

Three commands moved messages to the correct stream. `agent inspect` prints its warnings
on stderr, so a redirected report holds only the report. `agent secrets check` keeps all
rows on stdout, and ends with one error that counts the missing secrets. `agent stats` no
longer reports an empty result as a failure. `agent` with no arguments prints its command
list on stdout, so `agent | less` works.
