## What's Changed
### Added: spell checking in the prompt input

Claude Code can underline misspelled words in the prompt input as you type, but it ships no spell checker of its own — it drives one installed alongside it, and until now the image had none, so the feature could not be turned on at all. The base image now carries `hunspell` and its dictionaries, and every `agent run` enables spell checking wrapper-wide, so it works in every project with no per-project setup. English and Russian are recognised **together** by default: hunspell accepts a word found in any of the dictionaries loaded, so a prompt that mixes the two checks cleanly instead of underlining every word of one language. The trade-off of loading several dictionaries is that a typo which happens to be a valid word in one of the others is not flagged. Set `AGENT_SPELLCHECK=0` to turn the feature off, or `AGENT_SPELLCHECK_LANG` to replace the dictionary list — for example `AGENT_SPELLCHECK_LANG=en_GB,de_DE`, which needs one `agent rebuild --full` to install the new dictionaries before launches pick them up. Either variable, when set explicitly, wins over whatever the global settings file holds; left unset, edits you made there by hand are preserved. Requires one `agent rebuild --full` after upgrading. See [docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/configuration.md).

### Changed: host paths for mounts declared in `Dockerfile.agent`

A `# agent-run-args:` line can mount host paths into the container, and anything it named that did not yet exist was left to Docker to create — as `root`, leaving directories your agent could not write and you could not delete without `sudo`. Those host paths are now prepared before launch and owned by you: a writable bind source is created if it is missing, and a mount whose container-side target sits under `/workspace` also gets its mountpoint created inside the project, so the shadow-volume pattern (`-v /workspace/node_modules`) stops leaving root-owned directories behind after a run. A read-only source is the exception and is never invented — a `:ro` mount whose host path does not exist now fails the launch with an error naming the mount, instead of quietly mounting an empty directory whose emptiness only surfaces later inside the container; create the path, or drop `:ro` to have it created for you. Sources are read the way Docker reads them, so `/srv/data` and `./scratch` both count as host paths while `cache:/cache` stays a named volume, and `~` is still not expanded because no shell stands between the directive and Docker. The container side of a mount remains the image's own job: create and `chown` a custom mount path in your `Dockerfile.agent`, as [ops/dockerfile-agent-guide.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/ops/dockerfile-agent-guide.md) now spells out. See [docs/docker-sandboxing.md](https://github.com/mayty/claude-agent-wrap/blob/0.10.0/docs/docker-sandboxing.md).
