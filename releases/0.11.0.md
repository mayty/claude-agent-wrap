## What's Changed
### Changed: the wrapper runs on a venv, and `agent` provisions it on the first run

`agent` no longer runs on the bare pinned interpreter. It runs on a venv that holds the
packages that
[bin/requirements.txt](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/requirements.txt)
pins by hash. `agent` also provisions that venv itself, so the setup is one `git clone`,
and one `source` line in `~/.bashrc`. See
[docs/getting-started.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/getting-started.md).

A new set of dependencies builds a new venv, and the copy that you run stays intact.
`agent update` re-provisions when the dependencies move. `agent inspect` reports a stale
venv on the `interpreter` row.
[bin/agent-bootstrap](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/agent-bootstrap)
now reports each step, and `agent` sends that narration to stderr. `rm -rf .python`
reclaims the old venvs, and the next `agent` command provisions again.

### Changed: the logs viewer updates on filesystem events, not a two-second poll

The [`agent logs`](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-logs)
background viewer used to re-walk every session directory on the host every two seconds,
whether or not anything had been written. It now watches the shared log store and the
project registry, and updates the one session a write belongs to. A request reaches the
browser within a fraction of a second instead of up to two, and an idle viewer stops
walking the tree at all. A full reconciliation still runs once a minute: it is what keeps
`usage.json` fresh for the statusline, rolls the daily totals over at the day boundary,
and notices log directories `agent cleanup` removed.

This adds [watchdog](https://pypi.org/project/watchdog/) as the wrapper's second runtime
dependency, so the next `agent` command builds a new venv — `agent inspect` reports the
old one as stale until it does. watchdog publishes no macOS wheel for the pinned CPython,
so on Darwin `bin/agent-bootstrap` builds it from its (still hash-verified) sdist, which
needs the Xcode command line tools.

**Install agent-wrap on a local filesystem.** Filesystem watches are accepted but never
delivered on a Windows drive under WSL2 (`/mnt/c/...`) and on network shares, so a checkout
there falls back to the once-a-minute pass. Your projects can live anywhere; only the
wrapper's own location matters, and `agent logs` warns when it is one of these.

### Fixed: a project's session count now matches the sessions it lists

The project table's `SESSIONS` number was produced by a different rule at startup than
after the first update, so it could change on its own and disagree with the list you get
by opening the project. A session shared by two members of a grouped transient project was
counted twice, and a session whose record file held nothing parseable was counted even
though the sessions view has nothing to show for it. Both are now counted the way the
sessions view counts them, from the moment the viewer starts.
