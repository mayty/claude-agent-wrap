## What's Changed
### Breaking: `agent` exits 2 on a usage error

Every verb used to exit `1` when it could not parse its arguments. It now exits `2`, the
POSIX convention for a usage error. Exit `1` still means the operation itself failed.
An unknown flag, a bad value and a missing argument all exit `2`. A bare `agent` prints
the verb list and exits `2`; it used to print the list on stdout and exit `1`. A script
that tests for exit `1` after a bad flag needs the new code.

Two error messages also changed. `agent logs --port` now names the range it accepts.
Help output starts with `Usage:` instead of `usage:`. Each usage line now reads
`[OPTIONS]` in place of the flag list. The flags stay below it, under `Options:`.

Every verb also accepts `-h` now, and a mistyped flag or verb gets a suggestion.
`agent run` is the one exception: it forwards `--help` to Claude Code, as it always did.

### Breaking: `agent secrets` is a command group, and rejects a wrong argument count

`agent secrets check|set|clear` requires a sidecar name, and `agent secrets cleanup`
takes none. Both rules held before. They are now usage errors with exit `2`, where they
used to print a sentence and exit `1`. Each action has its own help. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-secrets).

### Added: `agent reindex` reads the LiteLLM log tree into a database

The wrapper now keeps an index of the LiteLLM request logs. It is a database at
`<wrap-dir>/.agent-launches/db/logs.db`. The [`agent logs`](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-logs)
viewer adds each request to it as the request arrives. `agent reindex` adds every request
that is not in it yet. Run the command on a host with logs that predate the index, or on
a host where the viewer has never run.

The command is incremental. Each session records how many bytes of its own log files the
index holds. A second run reads nothing past those marks. It reports the number of
sessions it changed and the number it looked at, so an up-to-date host reads `indexed 0
request(s) from 0 of 613 session(s)`. The command names any session it cannot read and
then exits `1`. One index update runs at a time on a host, so the command also exits `1`
when the viewer or another `agent reindex` holds the lock.

The new `--prune` flag applies age-based retention after the index is up to date. It
needs `AGENT_LOGS_RETENTION_DAYS`, and it deletes log files. See the retention entry
below.

The sidecar also stops writing a `meta.json` file into each session directory. That
file cached five facts about a session. The index holds them as columns now, and nothing
reads the file. An existing `meta.json` stays where it is, and `agent cleanup` removes
it with the directory that holds it.

`agent stats` and the viewer's project and session lists now read this index. They show
the requests the index holds. `agent run` starts the viewer, so that is normally every
request. `agent stats` writes nothing, and it reports when the index is behind the log
files:

```
! 12 of 613 session(s) are behind the log files; totals may understate spend. Run: agent reindex
```

### Added: age-based retention for request logs, off by default

The LiteLLM log tree grows without limit. Nothing rotated it before this release. Set
`AGENT_LOGS_RETENTION_DAYS` to a number of days to change that. A session with no
activity for that many days is then deleted. Its log files and its rows in the index go
together.

Retention is off unless you set the variable. Unset, empty and `0` all mean off. This
default is deliberate. A session's log files are the only record of its spend.
`agent stats` loses that spend for good when retention takes the session. There is no
archive to restore it from.

Two commands apply it, and you run both on purpose. `agent cleanup` surveys the expired
sessions first. It names the count, the age and the size in the preview, above its one
confirmation prompt. `agent reindex --prune` applies retention straight after it updates
the index, and asks nothing. The flag without the variable is a usage error.

A session is as old as its newest request. A conversation you return to every week never
expires. Two kinds of session are never deleted, whatever their age. The first carries no
timestamp on any record, so there is no age to compare it against. The second holds bytes
the index has not read yet. Deleting that one would destroy requests nothing has shown
you.

See [docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/configuration.md#agent_logs_retention_days-request-log-retention).

### Changed: `agent cleanup` deletes a project's spend with its logs, and reclaims unreachable index content

`agent cleanup` deletes the request-log directories of projects that are gone. It used
to copy their token counts into `<wrap-dir>/.agent-launches/orphaned-usage-archive.json`
first, and `agent stats` read that file. Those counts kept appearing under the
`<orphaned>` row forever. The archive is gone. A deleted log directory's spend now
leaves `agent stats` with it.

The confirmation prompt says so before it asks. Your existing
`orphaned-usage-archive.json` is left where it is and is never read or removed. It is
the only copy of the spend of log directories you have already deleted. Run
`agent stats` before a cleanup to record what you are about to lose. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-cleanup).

Every run of the command now also reclaims content that no request in the index reaches.
A session leaves such content behind when its log file is replaced instead of appended
to. A deleted project leaves behind everything that only its own requests used.

The preview tells you that the sweep runs. The summary reports what it reclaimed, and
the database file shrinks by that much. The command skips the sweep when another process
holds the index lock. The next `agent cleanup` reclaims the content instead.

The same pass applies retention when you have set `AGENT_LOGS_RETENTION_DAYS`. Expired
sessions are deleted first, and the sweep then reclaims what they held.

### Breaking: `~/claude_keys.json` is no longer imported

The wrapper used to copy any keys it found in `~/claude_keys.json` into the encrypted
secrets store and then delete the file. That import shipped in 0.8.0 and is gone.
Nothing reads the file now, and nothing removes it.

This changes nothing on a host that already ran 0.8.0 or later: the import ran on the
first such run, and the file was deleted then. On a host upgrading straight from 0.7.x
or earlier, open the file and re-enter each value with
[`agent secrets set <sidecar>`](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-secrets),
then delete it.

### Changed: `agent inspect` reports the request index

The details table has a new `request index` row, below `logs storage`. It reports the
size of the index, and the number of sessions and requests in it. It also reports how
long ago the index was last written to. A host that has never indexed a request reads
`never ingested` in place of an age.

The row turns yellow when indexed sessions are behind their log files. It gives the
number and points at `agent reindex`. `-l`/`--lite` does not measure that number, and
the row then says nothing about it. In `-j`/`--json` output, `index_behind` is `null`
for that case, which is not the same as `0`.

### Changed: the wrapper runs on a venv, and `agent` provisions it on the first run

`agent` no longer runs on the bare pinned interpreter. It runs on a venv that holds the
packages that
[bin/requirements.txt](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/requirements.txt)
pins by hash. `agent` also provisions that venv itself, so the setup is one `git clone`,
and one `source` line in `~/.bashrc`. See
[docs/getting-started.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/getting-started.md).

A new set of dependencies builds a new venv, and the copy that you run stays intact.
`agent update` re-provisions when the dependencies move. `agent inspect` reports a stale
venv on the `interpreter` row.
[bin/agent-bootstrap](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/agent-bootstrap)
now reports each step, and `agent` sends that narration to stderr. `rm -rf .python`
reclaims the old venvs, and the next `agent` command provisions again.

### Changed: the logs viewer reads the request index, and updates on filesystem events

The [`agent logs`](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-logs)
background viewer used to re-walk every session directory on the host every two seconds.
It now watches the shared log store, and it updates the one session a write belongs to.
A request reaches the browser in a fraction of a second instead of up to two. An idle
viewer stops the walk of the tree.

The viewer also reads the request index in place of the log files. It sends each message
of a session once, and each request refers to the messages it used. The longest session
in a 2.2 GB log tree holds 131,000 message references and 2,442 distinct messages. It
now opens with a transfer of 12 MB in place of 59 MB. The refresh each second sends the
new requests alone, which is tens of kilobytes.

A long string now arrives with the message that holds it. The viewer used to fetch those
strings separately, and it showed a spinner until they came.

A full reconciliation still runs once a minute. It keeps `usage.json` fresh for the
statusline. It rolls the daily totals over at the day boundary. It picks up a project you
registered since the last pass.

This adds [watchdog](https://pypi.org/project/watchdog/) as the wrapper's second runtime
dependency, so the next `agent` command builds a new venv — `agent inspect` reports the
old one as stale until it does. watchdog publishes no macOS wheel for the pinned CPython,
so on Darwin `bin/agent-bootstrap` builds it from its (still hash-verified) sdist, which
needs the Xcode command line tools.

**Install agent-wrap on a local filesystem.** Filesystem watches are accepted but never
delivered on a Windows drive under WSL2 (`/mnt/c/...`) and on network shares, so a checkout
there falls back to the once-a-minute pass. Your projects can live anywhere; only the
wrapper's own location matters, and `agent logs` warns when it is one of these.

### Changed: tab completion comes from the parser, and no longer lists flags on an empty word

Completion still needs no generated file and no `make` step. It now answers from the same
command definitions that parse the real command line. Type a `-` to see the flags of a
verb; an empty word offers nothing, because no verb takes a positional. A flag you have
already given is not offered a second time, and `agent secrets check <TAB>` still
completes the sidecar names. `agent run <TAB>` no longer falls back to file names.

**Re-source `agent-wrap.bashrc`**, or open a new shell, to pick up the new completion
function.

### Changed: the project registry is a SQLite database, and `projects.txt` is imported once

The registry of directories you have launched from moved out of
`<wrap-dir>/.agent-launches/projects.txt` and into the `projects` table of
`<wrap-dir>/.agent-launches/db/projects.db`. The text file stored paths in a compressed,
grouped encoding that could not be appended to, so every launch rewrote the whole file and
two launches at once could lose one of the two registrations. A row per path ends both, and
gives the registry somewhere to keep per-project facts the old format had no room for --
it already records when each project was first and last launched from. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-run).

Nothing is required of you beyond one launch. The first `agent run` after the update
reads any existing `projects.txt` and writes its paths into the database; a full
`agent cleanup` does the same. Your `projects.txt` is left exactly where it is and is
never written to or removed -- it is the only copy of the old registry, so it stays
recoverable by hand. Once the database has rows it is not read again.

Until that first launch, `agent stats`, `agent inspect` and the `agent logs` viewer
report no registered projects. Each one tells you to run `agent run` once. Only the
commands that write the registry perform the import.

### Changed: the base image is Ubuntu 26.04

The `claude-agent` base image now starts from Ubuntu 26.04 LTS. Every tool the image
installs from the distribution moves to that release. ImageMagick is the one that changes
behaviour: the clipboard shim on WSL2 now calls `magick` in place of `convert`. Image paste
from the Windows clipboard works as before.

The wrapper applies this on its own. Your next `agent run` rebuilds the base image and each
project image on top of it. That one run takes several minutes longer than usual. No
command and no configuration file changes.

### Changed: byte sizes read in IEC units

`agent inspect` and `agent cleanup` write a byte size as `2.5 GiB`. The old output was
`2.5GB`. The wrapper always divided by 1024, so the unit names now match the arithmetic.
A size above a terabyte gets its own unit. The old output stopped at gigabytes, so a
3 TiB log tree read as `3072.0GB`. The `-j`/`--json` output carries the raw number, and
that number does not change.

### Changed: `NO_COLOR` and `FORCE_COLOR` control the colour of the output

Set `NO_COLOR` to any value, and the wrapper writes no colour. Set `FORCE_COLOR`, and the
wrapper keeps the colour in a pipe or a file. A terminal with `TERM=dumb` gets no colour.
The wrapper read none of these settings before this release. It still drops the colour
when the output is not a terminal.

### Changed: the spinner clears its line when the work ends

A slow operation draws a spinner on a terminal. The spinner left its last frame on the
screen. It now removes the whole line. An operation with a result still writes that
result on a line of its own.

### Fixed: a project's session count now matches the sessions it lists

The project table's `SESSIONS` number was produced by a different rule at startup than
after the first update, so it could change on its own and disagree with the list you get
by opening the project. A session shared by two members of a grouped transient project was
counted twice, and a session whose record file held nothing parseable was counted even
though the sessions view has nothing to show for it. Both are now counted the way the
sessions view counts them, from the moment the viewer starts.

### Fixed: `agent logs --stop --port 8765` is refused

`agent logs --stop` takes no other argument. It refused `--port` with any other value,
but accepted the default port `8765` written out in full, and then ignored it. It now
refuses `--port` whatever the value.

### Fixed: the wrapper reports a Claude Code prerelease as an update

`agent inspect` compares the Claude Code version in an image with the newest published
one. A published version with a prerelease tag, such as `2.1.0-beta.1`, did not compare.
The row then reported no update at all. The wrapper now compares these versions
correctly.

### Fixed: a table stays aligned around a wide character

A path with Chinese, Japanese, Korean or emoji characters moved the table borders out of
line. `agent inspect` and `agent stats` measured each such character as one column wide.
A terminal draws it two columns wide. The wrapper now measures the width the terminal
uses.

### Fixed: a table title reads in one colour

The line above each table in `agent inspect`, `agent stats` and `agent cleanup` is dim.
On a terminal, the digits inside it were recoloured and the brackets around them
emboldened, so `Sidecars (3):` read in three colours. The whole line is now dim. A title
that contains square brackets also kept the brackets and lost the words between them.
Both read as written now.

### Fixed: `# agent-run-args:` keeps a path that contains a space

A `.claude-agent-wrap/Dockerfile` can pass extra `docker run` flags. The wrapper split
the value at every space, so a quoted path with a space became two arguments. Write the
path in quotes, and the wrapper now keeps it whole.

### Fixed: the wrapper reads a Dockerfile instruction that spans two lines

A `.claude-agent-wrap/Dockerfile` can end a line with `\` and continue the instruction
below. The wrapper read only the first line of such an `EXPOSE`, and missed every port
after it. A lowercase `from` or `expose` also went unread. The wrapper now reads both
forms.
