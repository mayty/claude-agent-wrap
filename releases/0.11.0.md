## What's Changed
### Breaking: `agent` exits 2 on a usage error, and `agent secrets` is a command group

A verb that cannot parse its arguments used to exit `1`. It now exits `2`, the POSIX
usage-error code. An unknown flag, a bad value, a missing argument and a bare `agent`
all exit `2`. Exit `1` still means the operation itself failed. A script that tests for
`1` after a bad flag needs the new code.

`agent secrets check|set|clear` requires a sidecar name, and `agent secrets cleanup`
takes none. Both rules held before, and they are usage errors now. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-secrets).

### Breaking: Intel Macs are no longer supported

[bin/agent-bootstrap](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/agent-bootstrap)
now stops on an `x86_64` macOS host, before it downloads anything. Apple Silicon Macs
and `x86_64`/`aarch64` Linux are unaffected, and so is WSL2. No configuration re-enables
the platform.

### Breaking: `~/claude_keys.json` is no longer imported

The wrapper used to copy any keys in `~/claude_keys.json` into the encrypted secrets
store. It then deleted the file. That import shipped in 0.8.0 and is gone. A host that
already ran 0.8.0 or later sees no change. On a host that upgrades from 0.7.x or
earlier, open the file. Re-enter each value with `agent secrets set <sidecar>`, then
delete the file.

### Added: the request index, `agent reindex`, and age-based retention for request logs

The wrapper now keeps an index of the LiteLLM request logs at
`<wrap-dir>/.agent-launches/db/logs.db`. The
[`agent logs`](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-logs)
viewer, `agent stats` and `agent inspect` read it.

`agent reindex` adds every request that is not in the index yet. Run it on a host with
logs that predate the index. The command is incremental, so a second run reads nothing
it read before. It reports the sessions it changed and the sessions it looked at.
`agent stats` writes nothing, and it reports when the index is behind the log files:

```
! 12 of 613 session(s) are behind the log files; totals may understate spend. Run: agent reindex
```

Set `AGENT_LOGS_RETENTION_DAYS` to a number of days, and a session with no activity for
that many days is deleted. Retention is off unless you set the variable, and
`agent stats` loses the spend of a deleted session for good.

Two commands apply retention. `agent cleanup` names the expired sessions in its preview.
`agent reindex --prune` applies retention after it updates the index. See
[docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/configuration.md#agent_logs_retention_days-request-log-retention).

### Changed: `agent cleanup` deletes a project's spend with its logs

`agent cleanup` deletes the request-log directories of projects that are gone. It used
to copy their token counts into `<wrap-dir>/.agent-launches/orphaned-usage-archive.json`
first, and `agent stats` read that file. The archive is gone, and a deleted log
directory's spend now leaves `agent stats` with it. The confirmation prompt says so
before it asks. Your existing file is left where it is, and nothing reads it or removes
it. See
[docs/shell-commands.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/shell-commands.md#agent-cleanup).

### Changed: the wrapper runs on a venv, and `agent` provisions and refreshes it itself

`agent` no longer runs on the bare pinned interpreter. It runs on a venv that holds the
packages that
[bin/requirements.txt](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/bin/requirements.txt)
pins by hash. `agent` provisions that venv itself, so the setup is one `git clone` and
one `source` line in `~/.bashrc`. A `git pull` that moves a dependency re-provisions the
venv on your next command. See
[docs/getting-started.md](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/docs/getting-started.md).

A failed venv update leaves the previous venv working and prints a message.
`agent inspect` then flags the `interpreter` row until a `bin/agent-bootstrap` succeeds.

On a Mac, the setup builds [watchdog](https://pypi.org/project/watchdog/) from source,
and that build needs the Xcode command line tools.

### Changed: the logs viewer updates on filesystem events

The `agent logs` viewer used to poll every session directory. It now updates the one
session that changed. A request reaches the browser in a fraction of a second. The
viewer also reads the request index, so a long session opens with a fraction of the
transfer.

**Install agent-wrap on a local filesystem.** Watches do not work on a Windows drive
under WSL2 (`/mnt/c/...`) or on a network share. A checkout there falls back to a full
pass once a minute. The `agent logs` command warns when the wrapper sits on such a
filesystem.

### Changed: tab completion comes from the parser, and no longer lists flags on an empty word

Completion now answers from the parser that reads the real command line. Type a `-` to
see the flags of a verb, and a flag you already gave is not offered again. An empty word
offers nothing. `agent secrets check <TAB>` still completes the sidecar names, and
`agent run <TAB>` no longer falls back to file names.

**Re-source [agent-wrap.bashrc](https://github.com/mayty/claude-agent-wrap/blob/0.11.0/agent-wrap.bashrc)**,
or open a new shell, to pick up the new completion function.

### Changed: the project registry is imported once

The registry of directories you have launched from moved into a database. The first
`agent run` after the update imports any existing
`<wrap-dir>/.agent-launches/projects.txt`, and a full `agent cleanup` does the same.
Your `projects.txt` is left where it is, and nothing writes to it or removes it. Until
that first launch, `agent stats`, `agent inspect` and the `agent logs` viewer report no
registered projects.

### Changed: the base image is Ubuntu 26.04

The `claude-agent` base image now starts from Ubuntu 26.04 LTS. ImageMagick is the one
that changes behaviour: the clipboard shim on WSL2 now calls `magick` in place of
`convert`. Image paste from the Windows clipboard works as before. Your next `agent run`
rebuilds the base image and each project image on top of it. That run takes several
minutes longer than usual.

### Changed: byte sizes read in IEC units, the wrapper reads `NO_COLOR` and `FORCE_COLOR`, and the spinner clears its line

`agent inspect` and `agent cleanup` write a byte size as `2.5 GiB`, where the old output
was `2.5GB`. A size above a terabyte now gets its own unit. Set `NO_COLOR` to any value,
and the wrapper writes no colour. Set `FORCE_COLOR`, and the wrapper keeps the colour in
a pipe or a file. A terminal with `TERM=dumb` gets no colour. A spinner now removes its
whole line when the work ends.

### Changed: the DeepSeek model mapping flattens onto one model, and Explore keeps the session model on DashScope and DeepSeek

The model mapping for the `litellm-deepseek` provider changed. The general, Opus, Sonnet,
Haiku, and subagent tiers now use `deepseek-flash[1m]`. A plain `agent run` on DeepSeek
therefore runs the flash model on every tier. `agent stats` now reports the cost of a
DeepSeek request.

On DashScope and DeepSeek, the built-in `Explore` agent now runs on the session model. It
used to run on a more expensive model than the session.

### Fixed: a project's session count matches the sessions it lists

The project table in the `agent logs` viewer counts each project's sessions. The number
changed on its own, and it disagreed with the sessions the project lists. The table
counted a session twice when two members of a grouped transient project shared it. It
counted a session whose record file held nothing parseable. The table now counts them
the way the sessions view does.

### Fixed: `agent logs --stop` refuses `--port` whatever the value

`agent logs --stop` takes no other argument. It refused `--port` with any value but the
default `8765`. It accepted that one value and ignored it. `agent logs --stop` now
refuses `--port` whatever the value.

### Fixed: `agent inspect` reports an update to a Claude Code prerelease

`agent inspect` compares the Claude Code version in an image with the newest published
one. A published version with a prerelease tag, such as `2.1.0-beta.1`, did not compare.
The row then reported no update. `agent inspect` now reports the prerelease as an update.

### Fixed: a table stays aligned around a wide character, and a table title reads in one colour

`agent inspect` and `agent stats` print each path inside a table. A path with Chinese,
Japanese, Korean or emoji characters moved the borders out of line. Both commands now
measure the width the terminal uses.

Each table also carries a dim title line. That line recoloured the digits inside it, so
`Sidecars (3):` read in three colours. A title that contains square brackets also lost
the words between them. The wrapper now writes the whole line dim, and both titles read
as written.

### Fixed: `# agent-run-args:` keeps a quoted path whole, and the wrapper reads a continued instruction

A `.claude-agent-wrap/Dockerfile` can pass extra `docker run` flags with
`# agent-run-args:`. The wrapper split the value at every space, so a quoted path with a
space became two arguments. The wrapper now keeps a quoted path whole.

Such a Dockerfile can also end a line with `\` and continue the instruction below. The
wrapper read only the first line of such an `EXPOSE`, and missed every port after it.
The wrapper now reads both forms.
