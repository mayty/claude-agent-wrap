## What's Changed
### Breaking: update opt-out env var renamed

The env var that disables the update check was renamed from `CLAUDE_AGENT_SKIP_UPDATE_CHECK` to `AGENT_SKIP_UPDATE_CHECK`. The old name no longer has any effect — if you set it, rename it. Set `AGENT_SKIP_UPDATE_CHECK=1` (or any non-empty value other than `0`/`false`/`no`) to opt out.

### Added: request logging in the LiteLLM sidecar

The shared LiteLLM sidecar now records every upstream model call — request and response — to per-session JSONL logs. This is the foundation for `agent logs` and the rebuilt `agent stats`; existing projects start logging on their next `agent run`.

### Added: `agent logs` command

A new `agent logs` command starts a local web viewer for the LiteLLM request logs. Pick a project and a session and read each exchange chat-style with full per-request context (system prompt, the message thread with tool_use/tool_result blocks, etc.) and usage.

### Added: DeepSeek provider

Route model traffic through DeepSeek. Set `AGENT_PROVIDER=litellm-deepseek` and add a `DeepSeekAPIKey` to `~/claude_keys.json`. See [README.md](https://github.com/mayty/claude-agent-wrap/blob/0.5.0/agent_wrap/providers/litellm_deepseek/README.md).

### Added: auto mode forwarding

`CLAUDE_CODE_ENABLE_AUTO_MODE` is now forwarded from the host shell into the agent container when set (verbatim, including `0`/empty, so you can both allow and explicitly disallow it). This matters on the default `litellm-bedrock` provider, where Claude Code's auto mode is otherwise unavailable; `litellm-dashscope` and `litellm-deepseek` speak the Anthropic protocol and already have it.

### Changed: `agent stats` now reads the LiteLLM logs

`agent stats` aggregates token and cost totals from the new LiteLLM logs instead of Claude Code's own session files, so usage is counted from what was actually sent upstream. Pricing now comes from the active provider, so the `--region` and `--refresh` flags are gone — the command takes only `[--days N]`. The previous implementation is still available as `agent legacy_stats`.

### Changed: update check is release-gated on `master`

The best-effort upstream check that `agent run` and `agent rebuild` run on every invocation — and `agent update` itself — now behaves differently per branch. On `master` it only prompts when a newer release **tag** is available and fast-forwards to that tag rather than the branch tip; untagged commits pushed after the latest tag no longer trigger a prompt. Other branches keep prompting on any upstream commit and update to the branch tip.

### Changed: Bedrock credential key

The Bedrock provider now reads a flat `BedrockBearerToken` from `~/claude_keys.json`. The old nested `ServiceSpecificCredential.ServiceCredentialSecret` still works for backward compatibility, but `BedrockBearerToken` is preferred.

### Changed: DashScope models

The DashScope provider now pins its models explicitly via environment variables rather than relying on config-side pattern matching. Sonnet moves from `qwen3.6-plus` to `qwen3.7-plus`, the effort level is set to `max`, and DashScope's prompt caching is disabled (it doesn't fit the Claude Code workflow).

### Other: documentation overhaul

The docs were reorganized into focused, per-topic guides under `docs/` — getting started, providers, configuration, container environment, volume mounts, shell commands, Docker sandboxing, Telegram notifications, and WSLg clipboard — with the secrets path and config env vars unified across them. The `default-CLAUDE.md` shipped to consumer projects was condensed: the `Dockerfile.agent` directive details were moved into a new `ops/dockerfile-agent-guide.md` that it points at (the `ops/` docs are mounted read-only into the container at `/opt/agent-wrap/`, unlike the `docs/` guides).
