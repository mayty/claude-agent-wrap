## What's Changed

### Breaking: Docker Engine 25.0 or newer is now required

`agent run` reads the daemon's version and stops with that reason when it is older than 25.0. The agent container is now placed on the wrapper's sidecar network *in addition to* any network the project declares in `agent-run-args`, and accepting more than one `--network` on `docker run` landed in Docker 25.0 (January 2024). A version the wrapper cannot read is treated as unknown rather than too old, so an unreachable daemon still reports the error it always did. Nothing else changed for hosts already on 25.0 or newer, and `agent rebuild` is not gated. See [Requirements](https://github.com/mayty/claude-agent-wrap/blob/0.12.0/docs/getting-started.md#requirements).

### Changed: `agent secrets` finds a repeated paste, and `agent secrets check` describes each secret

A secret pasted twice into the prompt was stored as-is. Nothing reported the mistake. The sidecar started, and the provider rejected the doubled credential later. `agent secrets set` now examines each entered value. When the value is several copies of one shorter string, the prompt says how many copies it found. It gives the length of the value and the length of one copy, with a masked hint for each. Answer `y` to store the single copy.

Any other answer keeps the value exactly as you typed it. An interrupt also keeps it. The prompt on the first `agent run` applies the same guard. `agent secrets check` now reports the length and a masked hint for each present secret, such as `sk***ef`. Base64 padding stays in the hint. The command never prints the value, and it prints `***` alone for a secret too short to hint at safely. See [`agent secrets`](https://github.com/mayty/claude-agent-wrap/blob/0.12.0/docs/shell-commands.md#agent-secrets).

### Changed: `agent secrets` prints its results as a table

`agent secrets check` now prints one table. The table gives a column to the key, the state, the length and the hint. A missing secret leaves the length cell and the hint cell empty. `agent secrets clear` and `agent secrets cleanup` now print the keys they remove as a table. Each table fits its columns to the content, and stays plain text in a pipe. See [`agent secrets`](https://github.com/mayty/claude-agent-wrap/blob/0.12.0/docs/shell-commands.md#agent-secrets).

### Fixed: a startup script can now create the network the project declares

A project that pairs `# agent-run-args: --network myproj-net` with a `startup.sh` that creates that network — the arrangement [the documentation recommends](https://github.com/mayty/claude-agent-wrap/blob/0.12.0/docs/docker-sandboxing.md#startup-script) — could not launch on a host where the network did not already exist. The sidecar was connected to the project's network before the startup script ran, so the launch aborted with `network 'myproj-net' (from agent-run-args) does not exist` and the script that would have created it never ran. This hit every cold host, and returned after any `docker compose down`. The agent now joins the sidecar network itself rather than the sidecar joining the project's, so nothing looks the project's network up before `docker run` — which already happens after the startup script.

### Fixed: a shared sidecar no longer holds a project's network open

Connecting a sidecar to a project's network had no matching disconnect. Sidecars are host-global singletons shared by every project on a provider and outlive any single run, so once one project's launch attached a sidecar, that endpoint survived until the last agent on that provider exited — and `docker compose down` in that project reported "network has active endpoints" in the meantime. The wrapper no longer modifies a sidecar's networks at all. The agent container runs `--rm`, so both of its endpoints are released when it exits.
