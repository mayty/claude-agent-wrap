## What's Changed

### Added: `litellm-anthropic-sub` provider for claude.ai subscriptions

A new [`litellm-anthropic-sub`](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/agent_wrap/domain/providers/litellm_anthropic_sub/provider.py)
provider routes Claude Code through Anthropic's own API,
`https://api.anthropic.com`, via its own LiteLLM sidecar — but, unlike every other
built-in provider, to spend a **claude.ai subscription** rather than
per-token API credits. It declares no secret: `agent secrets check litellm-anthropic-sub`
reports it needs none, so `agent secrets set` never prompts for it. Instead, authenticate
once per machine with a one-time in-container `/login`; the resulting claude.ai
credential persists across every project and every `agent run` afterward. `agent stats` records
its usage exactly as it does for any other provider — the same token counts, models, and
per-project rows — and prices it at a truthful `$0.00`, since a subscription has no marginal
per-token cost; for how much of the subscription itself you have spent, use `/usage` in Claude
Code or your usage view on claude.ai. In the statusline, the top-right segment shows the
five-hour subscription window as a `Usage (resets at 18:00):` bar, replacing the daily
token-and-cost readout the other providers show there. Select it with
`AGENT_PROVIDER=litellm-anthropic-sub agent run`; see
[docs/providers.md](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/docs/providers.md)
and the provider's own [README](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/agent_wrap/domain/providers/litellm_anthropic_sub/README.md)
for credential setup and gateway-mode side effects (Remote Control, fast-mode checks,
and MCP tool search behave differently under a custom `ANTHROPIC_BASE_URL`).

It is also the only provider whose containers leave Claude Code's non-essential traffic enabled.
Everywhere else the wrapper injects `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, which also
suppresses feature-flag evaluation against Anthropic's backend; here that evaluation is exactly
what makes Remote Control and `/usage` work, so the flag is omitted and `DISABLE_AUTOUPDATER=1`
takes its place. A custom provider keeps the old behavior unless it opts out. See
[docs/container-environment.md](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/docs/container-environment.md).

### Added: `AGENT_TIMEZONE` for stats and statusline times

`AGENT_TIMEZONE` names an IANA zone (e.g. `Europe/Warsaw`, `America/New_York`) used wherever the
wrapper would otherwise fall back to ambient system time. It sets the `agent stats` day boundary
when `AGENT_DAY_START_UTC` is unset — the more specific `AGENT_DAY_START_UTC` still wins when both
are set — and `agent inspect` names it as the source of the resolved boundary, under `--json` as
well as in the printed report. It is also forwarded into the container, so the
`litellm-anthropic-sub` statusline reports its subscription "resets at HH:MM" in that zone rather
than the container's own local time, which is otherwise UTC since nothing sets `TZ` in the image.
A zone offset by a half hour rounds to the nearest whole hour, because the day boundary is a whole
number of hours: `Asia/Kolkata` at UTC+5:30 buckets as though it were UTC+6, as do
`Australia/Adelaide`, `Asia/Tehran`, and `Asia/Kathmandu`. An unknown zone name is a hard error
rather than a silent fallback, matching `AGENT_DAY_START_UTC` — and since the zone is resolved as
the wrapper starts, a typo fails every `agent` subcommand, not only `agent stats`; the
in-container statusline, which must never crash the prompt, instead ignores it and falls back to
container-local time. The
[`agent logs`](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/docs/shell-commands.md#agent-logs)
viewer is unaffected — it renders timestamps in the browser's own timezone. See
[docs/configuration.md](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/docs/configuration.md#agent_timezone-display-timezone).

### Changed: per-project state now covers the session scratchpad and MCP logs

The per-project mount set introduced in 0.3.0 now reaches two paths that previously existed only
inside the container. Claude Code's per-session temp tree — the scratchpad it is directed to use
for every temporary file — is mounted from `$(pwd)/.claude/claude-tmp/`, so work an agent leaves
there outlives the container. Previously a session's transcript persisted while the scratchpad
files it referenced did not, so resuming with `--continue` or `--resume` left the agent holding
paths that had silently ceased to exist. The whole tree comes across, not only the scratchpad, so
the output of background commands and the transcripts of subagent runs survive a resume as well.
Alongside it, each MCP server's log is mounted from `$(pwd)/.claude/mcp-logs/`, so a server that
fails to start stays diagnosable after the container exits. Neither is garbage-collected —
per-session directories accumulate under `.claude/claude-tmp/` and are yours to prune. The
in-container briefing tells agents which paths now persist, so an agent can rely on its
scratchpad outliving the session. See
[docs/volume-mounts.md](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/docs/volume-mounts.md),
which also names the in-container path each is mounted at — it depends on the container's
effective user, so it differs between rootless and rootful Docker.

The base image now pre-creates the MCP log path's parent directories, so existing installs must
rebuild once after upgrading:

```bash
agent rebuild --full
```

Without it, Docker creates those parents owned by root and the agent loses write access under
`~/.cache`. A `Dockerfile.agent` that sets its own `# agent-user:` must likewise create
`~/.cache/claude-cli-nodejs` for that user itself.

### Changed: the statusline's context row

The bundled
[statusline](https://github.com/mayty/claude-agent-wrap/blob/0.9.0/ops/statusline.py)'s context row
now carries the session id after the percentage — `47% context · <session-id>` — on every provider,
so the id is at hand for `--resume` or for finding a session in the `agent logs` viewer without
leaving the prompt. Its colour is also decided purely by how much of the context window is used; a
session Claude Code flags as having exceeded 200k tokens no longer shows red while its context use
is still low.

### Improved: the `agent logs` viewer

A request's tool definitions are now browsable rather than a JSON dump. The full-detail view
rendered the entire tool array as one enormous pretty-printed blob; it now opens with a `12 tools`
header and a row of tool-name pills, so you can see what a request had access to without expanding
anything, and gives each tool a card carrying its name, a one-line description snippet, and its
parameter count. Expanding a tool adds its full description behind a toggle and a table of
parameters with types, required markers, enum values, defaults, and constraints written out as
phrases like `1–4 items` or `length ≥1`, with nested object parameters indented into their own
sub-tables. The Anthropic, OpenAI, and Bedrock tool encodings are all understood, and anything the
structured view does not model is still shown rather than dropped, so nothing visible in the old
dump is lost.

A reply that was cut short now says so. A response that reached its token limit, or that the
provider stopped for content filtering, is reported as a successful request, so the viewer drew it
as an ordinary answer that simply stopped mid-sentence with no explanation anywhere on the page.
Such a response now carries a notice naming the reason, and the token limit it hit, in both the
transcript and the full-detail view. The reason is read from the stored response, so sessions
logged before upgrading gain the notice too.

Auto-approval turns render correctly against Claude Code's current classifier. Recognising them
relied on marker text that the newer severity-based classifier prompt no longer contains, so those
requests fell through to the ordinary renderer as a full-size turn holding the entire reviewed
transcript and a reply full of raw markup, with no `auto` badge and no verdict. They are compact
again, the verdict now carries the severity score and the rule that matched —
`✗ Blocked · 85 · Destructive File Operation` — and the action under review reads as its tool name
plus pretty-printed input, instead of a mislabelled fragment of JSON trailed by several unrelated
actions. Requests in the retired format still render as they did.

The short requests behind the CLI's spinner caption no longer dominate a session. Each resends the
whole conversation and tool list to produce a three-word summary, and each was drawn as a full-size
turn duplicating that conversation. They now collapse to a compact block showing the caption
produced, the previous caption the model was told not to repeat, and a `STATUS` badge in the
caption line. Their cost and context line is deliberately kept — these calls are pure overhead, so
what they cost is the interesting part.

### Fixed: a failed request appears where it happened

A request that failed sorted ahead of the entire conversation, so one that failed midway through a
session was drawn as its first turn — before the session had started — and shifted the turn
numbering of everything after it. Failures now hold the position they actually occurred in, while
a session's genuinely first or last request still sorts first or last.

### Fixed: concurrent agents in one project directory

Claude Code's background daemon — the one behind `& <prompt>` jobs and `claude agents` — and its
live-session registry are now private to each container instead of shared by every agent launched
in the same directory. Both are keyed internally by process id, and every container runs its agent
as PID 1, so a shared mount had each agent resolving the others' process ids against its own
namespace: two agents in one project wrote the same session-registry record, and each could
displace the other's daemon through a lock whose recorded pid meant nothing on the far side. Each
container now gets its own subtree under `$(pwd)/.claude/instances/<instance-id>/`, removed when it
exits. One is left behind only when the wrapper itself dies without getting to clean up — a killed
container still runs its cleanup — and a later `agent run` in that project collects it once no
running container claims it and it has sat idle for an hour. See `docs/volume-mounts.md`.

Upgrading leaves the old project-level copies behind. They hold no state worth keeping, and are
safe to remove from any project you have run an agent in:

```bash
rm -rf .claude/{daemon,daemon.lock,daemon.log,daemon.status.json,session-state}
```
