# Release 0.3.0

## Highlights

### LiteLLM sidecar + pluggable provider layer (#1)

Model traffic now flows through a shared LiteLLM sidecar container instead of going to Bedrock directly, opening the door to observability layers (Langfuse, etc.) without touching Claude Code itself.

- New **provider plugin** tree under `providers/`. The launcher selects one via the `AGENT_PROVIDER` env var (default `litellm-bedrock`). Drop a new directory in to add a backend — auto-discovered, no central registry.
- Default **`litellm-bedrock`** provider owns a single shared `agent-wrap-litellm` container, fronted by a Docker user-defined bridge `agent-wrap-net`. Lazy-started on first `agent` launch, refcounted across parallel agents, stopped automatically when the last agent exits. The image is pinned to `ghcr.io/berriai/litellm:v1.83.14-stable`.
- The user's Bedrock bearer token is now scoped to the sidecar only — `claude-agent` containers never see it. Inside the agent, `AWS_BEARER_TOKEN_BEDROCK` carries the proxy's auto-generated master key instead.
- `AGENT_USE_HOST_NETWORK=1` (WSL workaround) now extends to the sidecar in cold-start launches, sidestepping the parallel-distro `iptables-legacy` FORWARD=DROP scenario end-to-end. First-launch-wins semantics: later launches adapt to the running mode rather than fighting it.
- New **`providers/template/`** with failing stubs and a README documenting the contract for forks that want a different routing implementation.

### Better project isolation (#2)

Per-project session and supervisor state no longer leaks across projects via the shared `.claude_config/` mount. The following paths are now overlaid with **per-project** mounts rooted at `$(pwd)/.claude/<subdir>/`:

- `projects/-workspace/` (transcripts), `sessions/` (live registry), `daemon/`, `jobs/`, `plans/`, `todos/`, `tasks/`, `shell-snapshots/`, `session-env/`, `file-history/`, `paste-cache/`
- Top-level files: `daemon.lock`, `daemon.log`, `daemon.status.json`, `history.jsonl`

**Migration:** existing installs should clear stale shared state once after upgrading:

```bash
rm -rf .claude_config/.claude/{sessions,daemon,jobs,daemon.lock,daemon.log,daemon.status.json,history.jsonl}
```

### Harden instructions to forbid `workspace` agent name (#3)

`default-CLAUDE.md` now explicitly forbids `workspace` as an `# agent-name:` value. That string is the in-container mount path, so a naive `basename "$(pwd)"` inside the container would resolve to it and silently produce the wrong tag. Agents are directed to read `$AGENT_NAME` (already sanitized) instead.
