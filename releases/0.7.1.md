## What's Changed

### Fixed: Telegram sidecar now works under rootless Docker

The Telegram decision sidecar added in 0.7.0 failed to start under rootless Docker. The wrapper omitted the `--user` flag on rootless hosts, so each container ran as the `USER` its image declares. The agent base image declares none, but the [Telegram sidecar](https://github.com/mayty/claude-agent-wrap/blob/0.7.1/agent_wrap/sidecars/telegram.py) image bakes in a non-root `USER`, which rootless Docker maps to an unprivileged subuid that cannot write the sidecar's host-owned log mount. Sidecar containers now run as `--user 0:0` under rootless Docker, which the daemon maps to the host user, so the mount is writable and the sidecar starts. This is scoped to rootless Docker; non-rootless behavior is unchanged. See [docs/docker-sandboxing.md](https://github.com/mayty/claude-agent-wrap/blob/0.7.1/docs/docker-sandboxing.md).

### Fixed: failed sidecar startups now surface the container's logs

When the Telegram sidecar or the shared LiteLLM sidecar fails its startup health check, the wrapper now streams the container's recent stdout and stderr straight to the terminal, so a startup traceback reaches you instead of being swallowed. Previously the launch aborted with no useful diagnostics.
